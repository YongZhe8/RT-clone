# Our Ray Tracer Roadmap

**Current position: lesson 0 — setup.** The teaching reference is prepared;
your own implementation has not started. Nothing here needs to be memorized.

## The route

| Phase | Our visible goal | Main idea |
|---|---|---|
| 0. Get ready | Run one tiny C++ program | Compile and run |
| 1. Make an image | Save and view a colored gradient | Pixels, RGB, loops, file output |
| 2. Add a sphere | Show one sphere against the sky | Vectors, rays, intersections |
| 3. Build a scene | Show several objects with matte and metal surfaces | Classes, object lists, material behavior |
| 4. Finish the first version | Improve image quality and add simple controls | Sampling, settings, integration |

A phase can take several short lessons. There is no one-weekend deadline.

## Each lesson

1. One small goal and the exact file or book section we need.
2. A short explanation of any prerequisite, with a concrete example.
3. A small code change together.
4. Run it and explain the result.
5. At a natural stopping point, a quick understanding check.

When something is confusing, we pause there and make the example smaller.
We do not add several new ideas while a prerequisite remains unclear.

## What we can change

The reference is a guide we can revise. We can slow down, simplify a feature,
change scene designs, or add an extension after the core works. Glass and camera
blur are optional. Required course features take priority once we see the rubric.

## The group

Everyone first understands the path from a pixel to a ray to a sphere.
After the first sphere, choose owners for objects, materials, rendering, and
scene controls. The 2–4 person options are in `docs/TEAM.md`; no role choice is
required today.

## The only next task

Identify your current C++ setup and get a tiny program to compile and run.
Then we begin with one pixel's color. You do not need to study the full source
or the full book before that lesson.
